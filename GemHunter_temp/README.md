  → 캡슐화 지키면서 상속 구조에서 필드 공유할 때 씀
- virtual / override / base 키워드로 다형성(polymorphism) 이해
  → 부모 타입 변수에 자식 객체를 담아도 실제 객체의 오버라이드된 메서드가 실행되는 것
  → EnemyBase.Setup()에서 MaxHp 먼저 계산하고 base.Setup()으로 currenHp 초기화하는 순서가 중요했음

  → `=>`는 매번 계산만 하고 값을 저장 안 함 (IsDead 같은 경우)
  → `{ get; set; }`는 값을 저장하는 그릇일 뿐, 자동으로 안 바뀌고 누군가 직접 대입해줘야 함
- IEnumerable / IEnumerator 차이

- UnityAction(델리게이트)과 콜백 패턴
  → 메서드 자체를 변수처럼 담아서 나중에 실행(Invoke)할 수 있게 하는 것

# 2026-09-02 학습 기록

## 오늘 배운 내용 
- 캐릭터가 적 방향으로 발사체를 발사할 때 방향을 잡는 방법을 이해했다. Vector2 연산으로 목표좌표에서 시작 좌표를 빼면 뱡향이 나온다. 이를 정규화로 방향만 남긴다. 이러면 이동 방향이 나오고, 시각적으로 회전을 하기 위해서는 각도 단위로 바꿔주는 Atan2 계산이 별도로 필요하다.
- Atan2가 뭔가 하니 유니티에서 제공하는 Mathf 함수 중 하나로 각도를 구해주는 메소드이다. Atan(y/x)이 기본인데, x와 y를 먼저 나눠버리면 부호(방향) 정보가 사라진다. 예를 들어 dx=1,dy=1(오른쪽 위)일 때와 dx=-1,dy=-1(왼쪽 아래, 정반대 방향)일 때 둘 다 y/x = 1이 되어 Atan(1)=45도로 똑같이 나온다. 즉 Atan만으로는 서로 반대 방향인데도 같은 각도로 계산되어 방향을 구분하지 못한다. 그래서 x, y를 나누지 않고 각각 따로 받아 부호까지 판단하는 Atan2(y, x)를 사용하면, 이런 경우도 정확히 구분된 각도(0~360도 전체 범위)로 계산할 수 있다.
- 또 극좌표에 대해 알게 되었는데 지금까지 이해한 내용은 평소쓰는 좌표계는 직교좌표 하고 하는 것이고 이는 가로로 얼마 세로로 얼마 이동했나로 위치를 표현한다. 극좌표계는 어느 방향으로 얼마나 멀리로 위치를 표현한다. 게임 개발에서 이 방향으로 이 만큼 떨어져 있음을 표현할 때 자주 쓴다. 근데 실제 화면으로 표현 할려면 직교좌표로 다시 나타내야 한다. 그 반환 공식이 x = cos(θ) * r, y = sin(θ) *r 이다. θ는 각도, r은 거리이다. (왜 sin,cos 인지는 삼각함수를 배웠으니   감이 잡힌다.)

- 그리고 enum의 기본 동작을 알게 되었다. 왜 가장 앞 속성에만 수를 대입해주나 했더니 값을 직접 써주지 않으면 바로 앞 항목에서 +1이 된다는 것이다. 이 규칙을 이용해서, 예를 들어 StatType처럼 일반 스탯(0번대)과 속성 보너스(100번대)를

나중에 한쪽에 항목을 추가해도 다른 쪽 번호와 안 겹치는 이점이 있다.
- Resources.LoadAll<불러올 타입>("파일명/") 이것을 통해 폴더 내부에 특정 에셋들을 불러올 수 있음을 익혔다. 반환값은 배열이다. 이걸 필요하다면 딕셔너리로 바꿔도 되고 되고 아니면 리스트로 변환가능 하다는 것을 익혔다.
